# 匿名聊天室

不用註冊、不用登入的聊天室。輸入一個代號就能進來,在公開聊天室講話,也可以邀請某個人私聊(對方按「接受」才會開始)。支援文字與照片,介面有六種語言,手機和電腦都能用。

**網址:https://32659-cloud.github.io/Web-page-1-/**

## 怎麼試用

聊天室需要有「另一個人」才看得到效果,所以請用**兩個視窗**測試:

1. 打開上面的網址,輸入一個代號進入。
2. 再開一個**無痕視窗**(或另一個瀏覽器、或手機),輸入另一個代號進入。同一個瀏覽器的一般視窗會被當成同一個人,所以第二個一定要用無痕視窗或別的裝置。
3. 兩邊都能看到對方在線上名單裡,可以在公開聊天室互相講話。
4. 在線上名單點對方的代號,按「邀請私聊」。對方會收到邀請卡片(有倒數計時),按「接受」就開始私聊。
5. 試試傳照片、收回訊息(點自己的訊息,再按「收回」)、結束私聊、右上角切換語言與深色模式。

## 功能

- **代號進入**:1 到 20 個字,不能和別人重複(不分大小寫),不需要密碼。
- **公開聊天室**:新進來的人看得到最近 100 則;文字上限 500 字(畫面一直顯示字數);電腦按 Enter 送出、Shift+Enter 換行,手機按送出鈕。
- **私聊**:邀請對方,對方接受才開始;同時最多 5 個私聊;邀請 60 秒沒回應自動逾時;被拒絕後 30 分鐘內不能再邀請同一個人。重新整理網頁,私聊和訊息都還在。
- **照片**:JPG、PNG、WebP,送出前在瀏覽器壓縮並先預覽;對話裡顯示縮圖,點開放大。
- **收回**:只能收回自己的訊息,內容真的會刪除,畫面留下「此訊息已收回」。
- **線上狀態**:別人斷線超過 15 秒才顯示「離開了」,15 秒內回來就不打擾大家。
- **顏文字與表情符號面板**:輸入框旁的按鈕,點一個就插入。
- **邀請提示**:瀏覽器在別的分頁時,分頁標題顯示「(1) 有新邀請」;邀請卡片有 60 秒倒數。
- **六種語言**:繁體中文、English、日本語、한국어、Español、Français。
- **淺色與深色模式**,預設跟隨系統。
- **防洗版**:每秒最多 3 則、相同內容 1 分鐘最多 3 次、照片每分鐘最多 3 張。

## 使用的技術

| 部分 | 工具 |
|---|---|
| 網頁(前端) | React、TypeScript、Vite、Zustand(畫面狀態)、react-i18next(多語言) |
| 後端 | [Supabase](https://supabase.com):匿名登入、Postgres 資料庫、Realtime 即時傳訊、Storage 照片儲存、pg_cron 定時工作 |
| 網頁空間 | GitHub Pages,用 GitHub Actions 在每次推送到 `main` 時自動測試、打包、發布 |
| 測試 | Vitest、PGlite(在記憶體裡跑真的 Postgres)、Playwright |

## 運作方式

網頁放在 GitHub Pages,只負責把檔案交給瀏覽器。瀏覽器裡的網頁直接和 Supabase 溝通,沒有自己架的伺服器。

- **身分**:Supabase 的匿名登入,瀏覽器第一次進來時自動取得一個身分,存在瀏覽器裡。
- **規則在資料庫裡**:送訊息、邀請、收回時的檢查(長度、速度、重複、冷卻、私聊上限……)都寫成資料庫函式,**不能靠繞過網頁來躲開**。
- **私聊只有兩個人看得到**:用資料庫的列級安全規則(Row Level Security)限制,連即時推送也只送給參與者;私聊照片放在私有的儲存桶,要用有時效的簽名網址才讀得到。
- **畫面和後端中間隔一層「通訊層」**:畫面只透過 `ChatService` 介面說話。這一層有兩個實作:`SupabaseChatService`(真實後端,預設用在正式網址)和 `MockChatService`(模擬後端,含機器人,用在開發階段與自動測試)。

更詳細的設計見 [`docs/architecture.md`](docs/architecture.md)。

## 在自己的電腦執行

需要 Node.js 20 以上。

```bash
npm install
npm run dev        # 打開 http://localhost:5173/
```

沒有設定任何金鑰時,預設使用**模擬版**(有機器人、資料存在瀏覽器裡,不需要網路後端)。要連真實的 Supabase,複製 `.env.example` 成 `.env.local`,填入自己的專案網址與 Publishable key,並把 `VITE_BACKEND` 改成 `supabase`。資料庫要先在 Supabase 網頁的 SQL Editor 依序執行 `supabase/migrations/` 裡的三個檔案(說明見 `docs/architecture.md` 12.4)。

`.env.local` 不會被上傳。**Secret key、資料庫密碼、Access token 不要寫進任何檔案。**

## 測試

```bash
npm test                # 小邏輯、模擬層規則、資料庫規則(PGlite),不需要網路
npm run build           # 型別檢查加打包
npm run test:e2e        # 3 個瀏覽器連真實 Supabase 走一遍(需先 npm run dev)
npm run test:security   # 直接對 Supabase 發請求,驗證第三個人讀不到別人的私聊、照片
```

後兩項會連到 `.env.local` 設定的真實專案,並留下少量測試訊息。

## 專案結構

```
src/
  protocol/    通訊約定:資料格式、錯誤代碼、規則常數(limits.ts)
  service/     通訊層:ChatService 介面、mock/(模擬)、supabase/(真實)
  state/       畫面共用資料
  features/    各個畫面(進入、線上名單、對話、邀請、照片、設定)
  i18n/        六種語言的文字
supabase/migrations/   資料庫:資料表、規則、函式、儲存桶、定時工作
tests/                 自動測試
docs/                  需求、架構、視覺設計、進度
```

## 已知限制

- **六種語言的文字沒有經過母語者校對**,繁體中文為主要語言。
- **沒有內容審核**:不擋髒話、不偵測不雅照片。使用者能做的只有收回自己的訊息、拒絕邀請、結束私聊。
- **照片檔可能殘留**:使用者直接關掉網頁來不及刪除的照片,會留在儲存空間(第一版沒有做自動清掃)。
- **免費方案的限制**:Supabase 免費專案閒置約 7 天會被暫停,需要到後台按「Restore」恢復;同時在線人數、每月流量與即時訊息數都有上限,適合小規模展示。
- 清除瀏覽器資料或換裝置,身分就變成另一個人;舊代號在保留時間內(沒有私聊 2 分鐘、有私聊 30 分鐘)無法使用。
